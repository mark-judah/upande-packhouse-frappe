Packhouse Backend Audit

Every number, KPI and filter on the packhouse dashboards was checked against how the packhouse actually works: line stems, box counts that count a mixed box once, the packing guide, the farm pack lists and the box labels. Nothing was changed. This is the findings list for the v2 backend.

The short version

Ordered stems are right almost everywhere: the stored line stems already account for mixed boxes and bunches. Nearly everything downstream of the order is wrong somewhere. Box totals are counted four different ways and none of them reads the packing guide. A broken link between order lines and pick lists puts other orders' packing and dispatch onto the wrong lines. Mixed boxes show 0 staged stems, or the whole box repeated on every variety. Bunches get added to stems. The stock pages promise stock the allocator will refuse. On top of the maths, four endpoints fail outright, and four take between 12 seconds and 101 seconds to load.

Most of these trace back to a handful of shared causes, below. Fixing them once, in shared backend services, fixes the numbers on every page that uses them.

Eight root causes

Each cause lists the proof found on real records and links to the individual findings.

1The order line → pick list link can't be trusted

Each order line stores the pick list it belongs to, but that field is copied when an order is duplicated and never cleared when a pick list is deleted. Pages join on it anyway.

Of 227 linked lines, 103 point to a pick list that no longer exists and 56 point to another order's pick list. Workflow shows 267 expected boxes for September where the packing guides hold 135. Order Summary shows 2,850 stems dispatched for 18 Sep; the real figure is 0.

2Boxes are counted four ways, none from the packing plan

Order boxes are a plain sum on some pages, a spec-aware dedup on others, and a group-only dedup on the allocation page and the order editor. The canonical dedup itself merges straight lines from a multi-variety mono-box spec into one box. Packed boxes count any box number on a draft pack list.

Stored order box totals are stale on 76 orders (SAL-ORD-2026-00128 stores 42, the real count is 6). SAL-ORD-2026-00382 claims 1 box holding 1,440 stems at a packrate of 720. Allocation Planning shows 395 boxes for 24 Sep against 307.

3Mixed boxes and bunches break the per-line maths

Staged and loaded stems multiply boxes by the straight-box packrate, which is empty on mixed lines. Packed stems for a whole mix group are repeated on each variety line. Fulfilment matches packed stems by variety and length, so a variety that appears twice gets counted twice. Group ids collide between different specs in one order.

Staged stems for mixed lines are always 0. SO-2026-00100 shows 120 packed against 20 ordered on all 6 of its lines. SO-2026-00380 reads 109% fulfilled; the truth is 55%. 28 legacy lines carry both mixed flags, so one is planned in two pick lists.

4Bunches and stems get added together

Box label contents are stored in bunches. Stem Movement adds them to stem counts. Workflow assumes every bunch is 10 stems. The order editor multiplies a per-stem price by bunches. Nothing stops a packrate that isn't a whole number of bunches.

OPL-2026-00017 shows 198 bunches; it has 132 (Bunch (15)). 260 order lines use bunch sizes other than 10. 26 live lines have a packrate that isn't a multiple of their bunch size, e.g. 63 stems with Bunch (10).

5Stale stored fields stand in for live numbers

Several pages read a field that was filled once and never kept up to date, instead of computing from the source.

6"Available stock" has three different definitions

The allocator reserves a whole bucket once it is on a discard request. The stock pages subtract discards per variety row, subtract allocations and discards twice where they overlap, and floor the result at different levels. Allocation Planning adds the same shelf once per order line that wants it.

Every live bucket on the site is on an approved discard request that nobody has carried out, so true available stock is 0. Stock Visibility shows 3,295, Avails shows 3,155, and Allocation Planning shows 855,803, which is more than the 606,241 stems on all shelves.

7Filters that don't filter

The rose-type filter compares a flat item group name, but varieties now sit in sub-groups. "Farm" means the shelf's farm on one page and the selling farm on another. Pages mix order creation dates with delivery dates. Some filters run after a row cap, and Allocation Planning truncates at 3,000 rows.

Production, 18–24 Sep: Sprays shows 7,140 stems against a true 89,545, and Standards shows 0 against 83,249. Allocation Planning on 19 Sep shows 188 of 316 order lines. With the farm filter on, the Stem Movement shelf ledger still counts every farm.

8Endpoints that fail outright, or write when they should only read

Four endpoints return an error or a silently empty answer on this site. Two feeds that should only read also create routes and settle trips on every page load.

Box Trace asks for a column that doesn't exist. The Scheduler reads a misnamed settings field on every site. Transfer Scheduling and Truck Routes fail because no transfer hub farm is set. Downgrades never prices anything because its currency join reads an empty field.

Fix before building v2

These are data and configuration problems. A new backend can't read correct numbers until they are fixed or deliberately worked around.

  1. Stop trusting the order line's pick-list link. Mark it "no copy", clear the 103 dangling and 56 cross-order links, and derive the relationship from the pick list rows instead.
  2. Correct the box key, then backfill stored totals. Fix the canonical dedup for straight lines from multi-variety specs, then recompute box totals on the 76 stale orders and the ordered quantity on 244 stale lines.
  3. Repair legacy mixed lines. 28 lines carry both mixed flags and 94 mixed lines have no group. Assign group ids on the server so specs in one order can't share a group.
  4. Make discard requests cover the whole bucket. The nightly auto-discard task keeps one variety per bucket. Decide what to do with the 10 approved requests that cover all stock on the site, which look like test data.
  5. Backfill the shelving log for the 2,872 shelf items that have no entry, and make every shelving path write one. Today 78% of shelf stock is invisible to the shelf ledger.
  6. Set the transfer configuration. Set the Remote Transfer Hub Farm, and give the transfer truck one consistent flag (KDT 177A is marked both internal and dispatch).
  7. Fix the two hard failures: the Scheduler's misnamed takt time field, and the Box Trace's non-existent consignee column.
  8. Keep test records out of live numbers: TEST box labels, SIM buckets and DISCARD-TEST buckets currently count in KPIs.

v2 backend shape

Shared services compute each kind of fact once, and every page reads from them. Pages stop doing unit conversions and roll-ups in the browser.

order_lines(day)

One row per order line: ordered stems, box key, allocated, issued, planned, packed, staged, loaded and dispatched. One grouped query per source, keyed by order line and pick list. Powers Workflow, Order Summary, Order Fulfilment, Allocation Planning and the Scheduler.

box_key(line)

The one box-dedup rule, used by the order save hook, the order list, the editor preview and every dashboard.

bucket_state()

One row per live bucket, split into discard-reserved, allocated and free so the three always add up to stems on shelf. Powers Stock Visibility, Avails, Cold Room and Allocation Planning.

transfer_buckets(day)

One row per physical bucket with its transfer stage, and trip claims returned by the server. Powers Transfer Scheduling, the Scheduler and Bucket Logistics.

flows(days)

One stock entry aggregate grouped by day and entry type, plus stage-warehouse balances. Replaces the 86 Stem Movement queries.

rose_type, page date, filters

Rose type from the item group tree. One date meaning per page. Every filter applied in SQL before any row limit. GET endpoints never write.
